2

Pegale ESTE prompt a Claude Code

Copialo entero y pegalo en el chat de Claude Code. Él diagnostica y arregla todo.
Soy el diseñador UX/UI del proyecto A51 Barbershop. Recién cloné el repo y creé el archivo .env.local con las claves que me pasó Was.

Necesito que hagas lo siguiente, en este orden, y me vayas explicando QUÉ encontrás en cada paso:

1. Confirmá que estamos parados en la carpeta correcta. Hacé `pwd` y mostrame el resultado. Si NO estamos en la carpeta `a51-barber`, movete ahí con `cd a51-barber`.

2. Verificá que existen estos archivos: `package.json`, `next.config.ts` (o .js), `.env.local`, carpeta `src/`. Listame qué encontraste y qué falta.

3. Si falta `.env.local`, avisame y paramos. Si está, abrilo (solo para verificar que tiene contenido, NO me lo muestres por seguridad) y confirmá que tiene al menos las variables `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`.

4. Si no existe la carpeta `node_modules/`, corré `npm install`. Esto tarda 2-3 minutos. Avisame cuando termine y si dio algún error.

5. Una vez instalado, corré `npm run dev` en background y dejame el log abierto para ver si arranca bien.

6. Si arranca, decime la URL local (debería ser http://localhost:3000) y confirmamelo.

7. Si tira algún error en cualquiera de los pasos, NO intentes arreglarlo solo: pegame el error exacto y esperame para que le avise a Was antes de tocar nada.

Importante: NO modifiques `package.json`, NO toques `.env.local`, NO hagas `npm update`, NO hagas commits. Solo diagnosticá y corré los comandos que te pedí.

Antes de empezar, leé el archivo `CLAUDE.md` (en la raíz del proyecto) para entender el contexto del proyecto.
Por qué este prompt: le dice a Claude Code exactamente qué chequear, en qué orden, y le pone límites para que no rompa nada. Va a ir mostrándote cada paso.

Antes de tocar cualquier cosa de diseño, hacele leer la documentación.
Antes de empezar a trabajar, leé estos 3 archivos en orden y hacé un resumen corto de cada uno para confirmarme que los entendiste:

1. CLAUDE.md (raíz del proyecto) — design system y reglas del proyecto
2. a51-barber/docs/feature-map-ux.md — inventario de pantallas
3. a51-barber/docs/design-handoff-progress.md — el tablero por dónde vamos

Después decime: qué superficie deberíamos atacar primero según el plan de Was, y qué archivos del código corresponden a esa superficie.
Con esto: Claude Code ya tiene todo el contexto que necesita para trabajar bien. Cualquier cosa que le pidas después la va a hacer respetando el design system y las reglas.
5

Cómo trabajar de ahora en más

El flujo de cada tarea.
  1. Antes de tocar código → crear branch: git checkout -b ui/nombre-corto
  2. Pedirle a Claude Code que haga el cambio (explicale qué pantalla, qué querés rediseñar)
  3. Ver el cambio en localhost
  4. Si te gusta → commit y push: Claude Code lo hace por vos si le decís
  5. Avisale a Was que pusheaste, te dice si está OK o pide cambios
  6. Cuando esté aprobado → Was lo mergea a producción
Regla de oro: nunca trabajes en la rama master. Siempre en una branch propia con el prefijo ui/.
